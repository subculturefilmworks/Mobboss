# Format scope and uncertainties

## MXF

The parser accepts a header partition at offset zero and definite BER KLV lengths. Header metadata local sets use two-byte tags and two-byte lengths. The Primer Pack maps each tag to a property UL; standard fields and Avid's project property (`a5fb7b25f61594b962fc3717492d42bf`) are selected by UL. Renumbering the project tag is covered by a fixture test. Avid dictionary definition sets are ignored as descriptions, rather than confused with actual metadata.

Material packages supply clip name, UMID and timestamps. File source packages are selected by their descriptor reference, and descriptors supply format, duration and rate. Duration is an integer count at the descriptor's edit rate (audio commonly uses 48,000 units/sec); divide by that rate to get seconds. PCM sample rate is exposed separately. Timestamps are MXF UTC values with four-millisecond fractional precision. Invalid/unknown rates are null.

The read budget is 512 KiB per file, including buffering. Reads stop at the declared header extent; buffering is restricted to that extent. Large KLV Fill values are sought over, never loaded. Body/footer partitions and essence keys stop parsing before their values. The sample reserves about 2 MiB for headers, but meaningful metadata occupies about 125–158 KiB. Fixtures contain only complete header KLVs; padding and essence are omitted. A guard test rejects any attempted read beyond the header.

Open headers with no declared metadata extent, run-in bytes before the initial partition, unsupported local-set length encodings, unsupported descriptor structures (including multiple-descriptor compositions), and headers exceeding the budget produce warnings and are skipped. These should become explicit supported variants with new fixtures before broadening the reader. A malformed file never makes PMR data masquerade as verified MXF metadata.

Codec names are conservative UL-family mappings. The sample contains DNxHR SQ, PCM, and DNxUncompressed alpha (16-bit alpha pixel layout). Unknown ULs are retained. DNxHR profile ULs 0x7124–0x7128 are mapped separately from the generic VC-3 family. PCM descriptors may omit SoundEssenceCompression; their class identifies PCM, while `codec_ul` remains null rather than inventing a compression label. VC-3 profiles outside recognized UL variants retain a generic DNxHD / DNxHR family label. Pixel layout provides bit depth for RGBA descriptors. Source classification (`kind`: captured/imported/render) remains null: the sample contains import-related attributes in several package graphs, but those do not yet establish the selected file's provenance. Names alone are insufficient evidence.

Codec family identifiers were checked against the [FFmpeg MXF UL registry](https://github.com/FFmpeg/FFmpeg/blob/master/libavformat/mxf.c); [FFmpeg’s DNx profile UL table](https://github.com/FFmpeg/FFmpeg/blob/master/libavformat/mxfenc.c) distinguishes DNxHR SQ (0x7127) from legacy DNxHD; no FFmpeg implementation code is incorporated.

## PMR and incremental comparisons

The bounds-checked reader follows [DJFio's MIT-licensed pmrtool.cpp](https://github.com/DJFio/MDV/blob/master/snippets/pmrtool.cpp) (2020). It detects both magic byte orders, accepts UID lengths of 2 or 8 four-byte words, and reads the declared entry count, length-prefixed strings, source UID and raw four-byte timestamp. Full little-endian PMR UMIDs store the material-number UUID's first 4/2/2-byte fields in native order; normalization matches all sample MXF file UMIDs. Short legacy eight-byte UIDs remain raw because their mapping to full UMIDs is not established. String bytes are treated as UTF-8 with replacement for undecodable legacy encodings; their precise code page is unknown. Empty project names remain empty.

PMR does not provide reliable size/mtime snapshots. A first scan reads headers for all unknown files even if PMR identifies them. Later quick scans compare actual disk size and nanosecond mtime to SQLite, plus PMR project/package identity. Header metadata remains authoritative. Changing content without changing size/mtime can evade quick detection; use deep to force verification. The PMR timestamp's epoch and relation to file mtime are unverified, so it is retained without treating it as a file modification time.

Diff compares PMR inventories where successfully parsed, otherwise the prior index. It reports missing names, names absent from the chosen inventory, and size/mtime changes since the prior scan. Discovery is recursive, case-insensitive for MXF/PMR/MDB extensions, does not follow directory symlinks, and accepts arbitrary MXF folders as a superset of Avid/NEXIS/OMFI layouts. OMF essence parsing is outside Phase 1. Non-ASCII Unicode paths are supported; non-UTF-8 paths are warned and skipped to avoid lossy SQLite key collisions.

SQLite stores absolute canonical scan roots, file paths/stats/metadata, folder/project rows and scan-run reports. Removed or invalid files are marked absent in the current scan scope. A scan's updates are transactional. Concurrent scans from separate processes and unusual filesystem races are not yet a supported workflow. `diff` currently performs a quick scan and refreshes the index; it never changes media.
